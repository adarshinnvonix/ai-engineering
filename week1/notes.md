**AI Engineering — Fundamentals**

# **1\. What Is AI Engineering?**

AI Engineering is the discipline of designing, building, evaluating, deploying, and maintaining software systems that use AI models—especially foundation models and large language models (LLMs)—as application components.

Traditional software is primarily programmed with explicit rules:

Input → Business Logic → Database/Services → Deterministic Response

An LLM application introduces a probabilistic model into the system:

User Input \+ Instructions \+ Context/Data → LLM → Generated Output or Tool Call

The engineering problem therefore extends beyond prompting. A production AI engineer must also control context, model selection, structured outputs, tools, retrieval, evaluation, latency, cost, security, and failure modes.

## **Key Principle**

An LLM is one component of an AI application—not the entire application.

# **2\. Generative AI, AI Developer, AI Engineer, Agents, and Agentic AI**

| Term | Meaning |
| :---- | :---- |
| Generative AI | AI systems that generate new content such as text, code, images, audio, or video. |
| AI Developer | A developer who integrates AI capabilities into applications, often through model APIs and application frameworks. |
| AI Engineer | An engineer who builds the surrounding production system: model integration, context/data pipelines, retrieval, tools, evaluation, observability, security, cost, and reliability. |
| AI Agent | An LLM-powered system that can select or invoke tools/actions to accomplish a task. |
| Agentic AI | A broader system design in which AI can pursue goals through multi-step planning, action, observation, and iteration. |

## **Example: Customer Support Assistant**

Simple LLM application:

User → LLM → Answer

Production-oriented system:

User → API → Authentication → Retrieve customer/order data → LLM → Validate output → Answer

The second system is an AI engineering problem because the model is only one part of the workflow.

# **3\. Where LLM Applications Fit in Modern Software**

A useful mental model is:

Frontend → Backend/API → AI Application Layer → Data/Tools → LLM Provider

* Frontend: chat UI, document upload, streaming response, citations, status indicators.  
* Backend: authentication, authorization, business logic, rate limits, orchestration, API integration.  
* AI application layer: prompts, context construction, structured output, retrieval, tool selection, agent workflows.  
* Data layer: relational databases, documents, object storage, vector stores, APIs.  
* LLM provider/model: generates text, structured output, tool calls, or other model-specific results.

# **4\. How LLMs Work**

## **4.1 Tokens**

Tokens are the units of text processed by an LLM. A token may correspond to a whole word, part of a word, punctuation, or another text fragment depending on the tokenizer.

* Input tokens are the text/context sent to the model.  
* Output tokens are generated by the model.  
* Token usage affects API cost.  
* Large prompts and large retrieved documents increase token usage and often latency.  
* Tokenization differs between model families.

## **4.2 Context Window**

The context window is the amount of input and generated context a model can process within a request/session boundary, depending on the provider and model.

Typical context components include:

* System instructions  
* Conversation history  
* Current user message  
* Retrieved documents  
* Tool results  
* Structured data supplied to the model

Important: a large context window is not equivalent to permanent memory. Context is information available to the model for a particular interaction; long-term memory requires an application-level mechanism.

## **4.3 Transformer — High Level**

Transformers are neural-network architectures that use attention mechanisms to model relationships between tokens. For AI engineering, understand the flow conceptually:

Text → Tokens → Model/Transformer Layers → Probability Distribution → Generated Tokens

Attention allows the model to weigh relationships between different parts of the input when producing representations and predictions.

## **4.4 Temperature**

Temperature affects the randomness of token sampling. Lower values generally produce more predictable/deterministic outputs; higher values generally permit more variation.

* Lower temperature is often useful for extraction, classification, or highly constrained outputs.  
* Higher temperature can be useful for creative generation and exploring alternatives.  
* Temperature does not mean intelligence. Increasing it does not make the model smarter.

## **4.5 Top-p**

Top-p (nucleus sampling) limits sampling to a set of likely next tokens whose cumulative probability reaches a specified threshold.

* Temperature changes the shape/contrast of the sampling distribution.  
* Top-p limits the probability mass considered during sampling.  
* Usually do not need to aggressively tune both at once.

## **4.6 Max Tokens**

Max tokens limits how much output the model may generate. It affects response length, potential cost, and latency.

## **4.7 Hallucination**

A hallucination is generated content that is unsupported, fabricated, or factually incorrect but may sound plausible.

Why hallucinations matter:

* LLMs generate likely continuations; they are not guaranteed truth engines.  
* A confident tone does not establish factual correctness.  
* Production systems should ground answers in authoritative data where accuracy matters.  
* Useful controls include retrieval, tool calls, structured outputs, validation, citations, and evaluation.

## **4.8 Reasoning Models vs Chat Models**

Different model families optimize for different workloads. Reasoning-oriented models may allocate more computation to complex multi-step problems, while general chat models may prioritize conversational quality, speed, or cost.

Model choice should depend on the task, not on the label alone.

* Simple extraction/classification → often a smaller or faster model.  
* Complex coding or multi-step reasoning → potentially a reasoning-oriented model.  
* High-volume simple tasks → cost and latency may dominate quality differences.
